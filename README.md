# Feather-Talk v2 재구현 (PWA)

[Feather-Talk v2](https://v2.feathertalk.live/)를 원본 번들 분석을 바탕으로 HTML·CSS·Vanilla JavaScript로 다시 만든 **비공식** 버전입니다.
원본 번들을 불러오거나 원본 서버에 연결하지 않고 혼자 동작합니다.

레이어로 나눈 캐릭터 PNG를 겹쳐 고개 회전(가짜 3D), 깜빡임, 마이크에 맞춘 입 움직임, 머리카락 흔들림을 주고,
라이브 화면을 OBS 등으로 캡처해 쓰는 도구입니다. 서버 없이 모든 데이터가 브라우저에 저장됩니다.

분석 근거·확인/추정 구분·미수집 자료는 [docs/ANALYSIS.md](docs/ANALYSIS.md)에 있습니다.

## 화면

| 주소 | 화면 |
|---|---|
| `/` | 편집기 (정식판) |
| `/live.html` (`/live`) | 라이브 (정식판) |
| `/beta/` | 편집기 (베타: 캐릭터 슬롯 10개, 몸 리깅, 확대·이동 등) |
| `/beta/live.html` (`/beta/live`) | 라이브 (베타) |
| `/multi/` | 멀티 설정: 여러 캐릭터 무대, 화면 캡처로 말하는 사람 감지 |
| `/multi/live.html` (`/multi/live`) | 멀티 라이브 |

괄호 안 주소는 Render 배포에서 원본과 같은 주소로 열리도록 연결해 두었습니다.

## 실행

빌드 단계가 없습니다. ES 모듈·서비스 워커·절대 경로를 쓰므로 **저장소 폴더를 웹 서버의 루트로** 띄워야 합니다.

```bash
python3 -m http.server 8080     # 또는 npx serve .
```

http://localhost:8080/ 접속. 마이크·카메라·화면 공유는 HTTPS 또는 localhost에서만 쓸 수 있습니다.

### Render 배포
Render 대시보드 → **New → Blueprint** → 이 저장소 (`render.yaml` 자동 인식, 정적 사이트).

## 구현된 기능

**편집기 (정식판)**
- 상단: 사용법, 백업 내보내기(`feathertalk-backup.json`), 불러오기, 기본 캐릭터로 되돌리기, 라이브 시작
- 미리보기: 마우스 따라보기 / 자동 흔들기 / 정면 고정, 표정 1~0, 눈 감기·깜빡여 보기·입 열기·말해 보기, 선택한 레이어만 진하게
- 끌어서 조정: 얼굴 중심, 얼굴 크기, 머리카락·장식 고정선, 눈 깜빡임 영역
- 레이어 목록·속성·전체 설정 전부, 자동 저장, 슬라이더 더블클릭 초기화

**베타 (`/beta`)** — 정식판 기능에 더해
- 캐릭터 슬롯 1~0 (우클릭 복사·붙여넣기, 다른 탭과 동기화)
- 몸 리깅: 관절 맞추기(좌우 대칭), 몸통 두께, 파츠별 뼈 자동 배정(양팔·양다리 한 장 포함), 따라가는 정도, 골반·무릎 움직임
- 연주 포즈 동작 1·2 (관절 끌어 회전/길이), 연주 미리보기, 연주 속도
- 부위 '고정', 몸 레이어 흔들림, 그림 비율 자동 인식, 확대·이동(휠·우클릭 드래그·핀치)
- 레이어/캐릭터/몸 리깅 탭, 접히는 묶음과 요약, ⓘ 설명, 시작하기 체크리스트

**라이브** — 마이크 입 움직임(민감도), 자동 깜빡임, 마우스 → 멈추면 자동 모션, 리깅 강도, 자동 모션 범위, 60/30fps, 배경색, 숫자키 표정(베타는 캐릭터 전환), 베타 확대·이동과 연주 포즈, 조작 막대 자동 숨김

**멀티 (`/multi`)**
- 16:9 무대에 캐릭터 최대 10명·오브젝트 배치 (끌어 이동, 점으로 크기), 겹침 순서, 배경색
- 화면 캡처(`getDisplayMedia`)로 SYNCROOM 레벨미터 / Discord 말하는 테두리 / 직접 고른 색을 감지해 말하는 캐릭터의 입과 연주 포즈를 움직임
- 자르기 영역, 캐릭터별 감지 영역, 화면에서 색 고르기, 판정 픽셀 수·여유값·유지 시간, 감지 막대
- 캐릭터 만들기 탭(베타 편집기와 같은 슬롯), 멀티 라이브

**추가 난이도 항목**: 웹캠 얼굴 추적(MediaPipe, 정면 맞추기, 좌우 반전, 눈 깜빡임 따라하기), 화면 공유 감지. 권한 거부·장치 없음·모듈 다운로드 실패·미지원을 구분해 안내합니다.

**PWA**: 설치 가능, 한 번 연 뒤 오프라인 실행

## 미구현

- `/legacy/*` (원본의 이전 버전 화면): 수집되지 않아 원본 사이트로 링크
- 원본 기본 캐릭터 그림: 수집되지 않았고 사용 권한도 불분명해 대체 그림 사용

## 기본 캐릭터 그림 바꾸기
`assets/`의 `bang.png, mouth.png, mouthopen.png, eyes.png, eyesclosed.png, face.png, body.png, back.png`를
같은 이름의 512×512 정사각형 PNG로 바꾸면 코드 수정 없이 기본 캐릭터가 바뀝니다.
원본 그림은 원작자에게 허락을 받은 경우에만 넣어 주세요. 대체 그림을 다시 만들려면 `npm i -D playwright` 후 `node tools/export-assets.mjs`.

## 테스트 결과 (헤드리스 Chromium 자동 테스트)
- 6개 화면 모두 콘솔 오류 없음 (개발 환경에서 막힌 글꼴·CDN 요청, 마이크 장치 없음, 의도한 오류 테스트 제외), 화면에 "null" 같은 잘못된 글자 없음
- 정식판: 레이어 추가·업로드·이름·슬라이더 스냅·초기화·표정·복제·삭제·끌어 정렬, 이미지 오류 표시, 얼굴 중심 끌기, 새로고침 유지, 백업 내보내기→다시 불러오기(업로드 파일 복원), 제공된 원본 백업 불러오기, 되돌리기 후 업로드 파일 정리
- 베타: 탭·묶음·툴팁, 슬롯 전환·복사·붙여넣기(슬롯마다 레이어 따로), 고정 부위, 몸 리깅 켜기·관절 끌기(대칭 반영)·포즈 회전(팔 아래쪽)·길이(다리 1.3배 제한)·연주 미리보기, 휠 확대, 시작하기 체크, 새로고침 유지, 정식판 저장값과 분리
- 베타 라이브: 휠 확대 저장·화면 맞춤, 숫자키 캐릭터 전환
- 멀티: 캐릭터 켜기, 오브젝트 추가, 순서, 무대 끌기·크기 조절과 저장, 감지 방식 전환, 감지 알고리즘(합성 화면으로 SYNCROOM·Discord 판정 확인), 캐릭터 만들기 탭에서 고친 내용 반영, 멀티 라이브 표시
- 모바일 375px 가로 넘침 없음 (정식판·베타·멀티), 오프라인 새로고침

## 남은 문제·한계
- 원본과 화면을 나란히 비교하지 못함 (개발 환경에서 원본 접속 불가)
- 실기기 마이크·카메라·화면 공유·MediaPipe 추적은 확인 필요 (개발 환경에는 장치·CDN·공유 화면이 없음)
- 개발 환경(헤드리스 SwiftShader)에서 다른 WebGL 탭을 연 채 멀티 무대를 열면 캐릭터 그림이 깨지는 현상을 몇 번 관찰함. 한 페이지 10명은 정상이고 재현이 일정하지 않아 소프트웨어 GPU 문제로 보이지만, 실제 GPU에서 확인 필요
- 목록 끌어서 정렬은 원본처럼 HTML5 드래그라 휴대폰 터치로는 안 됨 (앞으로/뒤로 버튼 사용)
- 520px 이하에서 상단 막대 고정을 푼 것은 원본과 다름 (화면 가림 문제)
- Render가 `404.html`을 없는 주소에 자동으로 쓰는지는 배포 후 확인 필요
