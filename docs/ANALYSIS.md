# Feather-Talk v2 분석 기록

근거 자료 (사용자 제공):

- `feathertalk_source_package.zip`: 원본 사이트에서 수집한 Nuxt/Vue 프로덕션 번들(`_nuxt/*.js`, `*.css`), 정적 DOM 스냅샷 `captured-page.html`, 수집 분석 `ANALYSIS_KO.md`

### 렌더링·움직임 (확인한 계산식을 독자 코드로 다시 작성)
- 머리: 얼굴 중심 구면 위 회전, z = 깊이×0.4 + 볼록×0.4×(1−r²)
- 몸: 발끝 기준 호흡 늘어남, 전체를 발끝 축으로 기울기·늘어남/납작함
- 눈 눌림 띠, 통통(눈 높이 축 세로 배율), 입 벌림(그림 불투명 영역 가운데 축, 가로 0.8~1·세로 0.5~1)
- 머리카락: 고정선에서 멀수록 회전·이동, 레이어별 스프링(탄성 20+2s, 감쇠 계수 출렁임 반영), 호흡 지연 출렁임
- 고개 스프링 k=64, 1/120초 고정 적분, 탄력에 따라 감쇠비 1→0.2
- 클리핑: 바로 아래 레이어 알파 0.5 이상을 스텐실로
- 깜빡임 70/40/110ms, 자동 2~6초 간격, 15% 확률로 두 번

## 2. 추가 확인이 필요한 화면 및 기능

| 항목 | 상태 |
|---|---|
| 실제 브라우저에서 원본과 나란히 비교 | 원본 접속 불가로 못 함. 번들 CSS 값을 그대로 옮겨 맞춤 |
| 실기기 마이크·웹캠(MediaPipe)·화면 캡처 | 개발 환경은 장치·CDN·화면 공유가 없어, 실패 시 안내까지만 확인. 감지 알고리즘은 합성 화면으로 확인 |
| 여러 WebGL 탭 동시 실행 | 개발 환경(헤드리스 SwiftShader)에서 다른 WebGL 탭이 열린 채 멀티 무대를 열면 캐릭터 그림이 깨지는 현상을 몇 번 관찰. 한 페이지 10명은 정상, 같은 조건 재실행 시 정상인 경우도 있어 실기기 GPU에서 재확인 필요 |
| 휴대폰에서 상단 막대 | 원본은 항상 상단 고정. 520px 이하에서는 고정을 풀었음 (의도적 변경) |
| `/legacy/*` 이전 버전 | 수집되지 않음. 원본 사이트 주소로 링크 |

## 3. 백엔드 또는 외부 서비스가 필요한 기능

원본은 서버를 쓰지 않는다 (편집기 문구 "별도의 서버를 운영하지 않아요", 저장은 모두 브라우저).

| 외부 의존 | 용도 | 실패 시 |
|---|---|---|
| `fastly.jsdelivr.net` Pretendard 글꼴 | 글꼴 | 기본 글꼴로 표시 |
| `cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@1.0.1` + `storage.googleapis.com` 얼굴 모델 | 웹캠 추적 (켤 때만 받음) | "얼굴 인식 모듈을 받지 못했어요" 표시, 마우스/자동 모션 유지 |
| 외부 이미지 주소 | 레이어 이미지 | CORS로 막히면 "이미지 오류" 배지와 안내 |
| 브라우저 권한 (마이크·카메라·화면 공유) | 라이브 입, 웹캠, 멀티 감지 | 권한 거부·장치 없음·미지원을 구분해 안내 |
